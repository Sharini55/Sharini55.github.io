AI Study Buddy

See code See it live

Problem Statement

STEM students are constantly overwhelmed by scattered, high-volume course materials — dozens of lecture slides, textbook PDFs, and unstructured notes, with limited time before exams. The core challenge isn't organizing this material; it's prioritizing and mastering the information quickly.

Students lack a direct, fast path from raw course files to high-yield exam preparation. Without a structured way to extract key concepts, self-assess, and identify knowledge gaps, students spend precious study hours passively skimming slides rather than actively practicing.

Target Users

STEM university students preparing for midterms and finals who need to turn dense lecture decks and PDFs into actionable, high-yield study resources.

Students who don't have hours to manually write practice questions or outline topics, and need targeted practice on what will actually be tested.

Solution

AI Study Buddy is a web-based study workspace where students upload raw course material, index it once, and generate AI-powered study guides and adaptive quizzes on demand. The workspace model means uploaded material persists across sessions, so students don't have to re-upload every time. Multiple workspaces support multiple subjects simultaneously.

The core loop: Upload material → Index → Generate study guide → Take quiz → Review weak areas → Generate targeted remediation guide or quiz → Retake.

Technical Architecture

AI Study Buddy is built with Python and Streamlit and deployed on Azure App Service, using a PostgreSQL database on Azure. Source files are parsed, chunked using LangChain, converted to vector embeddings, and stored for semantic retrieval.

Study guide generation uses a Skeleton-of-Thought parallel processing framework. Instead of generating the full guide sequentially, the system generates a topic skeleton first, then generates all sections in parallel using a ThreadPoolExecutor, reducing perceived latency from 91 seconds to under 20 seconds. AI generation is powered by Google's Gemini 2.5 Flash via the Gemini API. API keys are stored in browser localStorage only and never sent to the server.

Features

Each feature below is summarized. Click the link to read the full PRD.

Feature 1: Generate Study Guide from Weak Areas

After a student takes a quiz, the app identifies topics where they answered incorrectly and tags them as weak areas. Instead of sending students back to the full study guide to hunt for those topics, the app generates a new study guide scoped only to those weak areas. This closes the loop between testing and targeted review, a flow Quizlet does not currently offer.

Feature 2: Generate Quiz from Weak Areas

Retaking the full quiz after getting things wrong means spending time on topics the student already knows. This feature generates a new quiz scoped only to weak-area topics, giving students concentrated practice on what they actually need to improve. If the entire quiz was answered incorrectly, the student is redirected to retake the full quiz with different questions rather than an empty weak-area quiz.

View full PRD →
Feature 3: Deep Dive and Cram Mode

A single study guide cannot serve students with different time constraints equally well. Deep Dive mode generates a comprehensive guide covering all indexed material in depth. Cram mode generates a focused guide based on bolded text, headings, and high-frequency concepts, prioritizing what's most likely to appear on an exam. If the material has no bolded text, the AI identifies important topics based on content frequency and fundamentals.

View full PRD →
Feature 4: Challenge Attempt Before Reveal

Study guides include challenge problems at the end of each topic section. Previously, the solution was immediately visible, allowing students to read the answer without attempting the problem, creating the illusion of understanding without actual recall. This feature requires students to submit at least one attempt before the solution is revealed. After submitting, the student's attempt and the full solution appear side by side, with an AI-generated evaluation identifying what they got right, what they missed, and which concept the gap points to.

View full PRD →
Feature 5: Configurable Quiz Question Count

The quiz previously generated a fixed 5 questions regardless of how much material was uploaded. For students with large workspaces covering multiple PDFs and lecture decks, the 5 questions provide superficial coverage. Students can now select 5, 10, 15, or 20 questions before generating. The recommended default is calculated from the number of indexed sections, approximately 2 questions per section, capped at 20. Cram mode defaults to 5; Deep Dive defaults to the material-based recommendation.

User Research

Six external beta users tested the app after public flyers were posted at ASU's Memorial Union, and Discord channels were used to recruit CS students. A structured feedback form collected responses regarding usability, points of confusion, and feature requests.

Two key findings emerged. First, users could not see which files had been uploaded after selecting them; the upload zone showed no confirmation until after clicking Index Materials, causing users to re-upload files they had already added. This is being addressed by adding filename confirmation immediately after file selection. Second, multiple users encountered API key errors with unclear messaging. The generic "check your API key and try again" error appeared for four distinct failure types: invalid key, network block, 503 from Gemini, and rate limit, making it impossible for users to self-diagnose. Updating error messages to be failure-specific is a priority for the next sprint.

One user explicitly requested a way to generate their Gemini API key from within the app. This informed the decision to add a direct link to aistudio.google.com next to the API key input in Settings, which has been added.

Competitive Analysis

AI Study Buddy and Quizlet AI solve adjacent problems, but at different points in the student workflow. Quizlet assumes students already have organized content. AI Study Buddy works upstream; it takes raw, unstructured course material and builds the structure. Quizlet's post-quiz experience offers a retake or a new quiz. AI Study Buddy's closed-loop remediation, which identifies weak areas, generates targeted content, and retests, is more structured and more adaptive.

Quizlet's meaningful advantages over AI Study Buddy currently: inline study guide interactions (highlight to ask, reword, explain), audio upload for lecture recordings, and a folder-based organization system for saved guides.

What I Learned and What's Next

The most important thing I learned is that onboarding friction kills everything downstream. A user who can't get past the API key setup never generates a guide, never takes a quiz, never experiences the core value. If I were to prioritize one thing before expanding features, it would be removing the API key requirement entirely by absorbing the cost on the backend and offering a freemium model with usage limits.

The second thing I learned from user research is that UI feedback at each step matters more than I expected. Users assumed their upload failed because they couldn't see the filename. They assumed the app was broken because the error message didn't tell them what actually went wrong. Small copy and feedback changes had more impact on user confidence than technical features.

What I'd build next, in priority order: email-based authentication to remove the password-reset gap, a progress dashboard showing quiz scores over time so students can see improvement, the challenge attempt feature (in progress), and audio upload support to close the gap with Quizlet.
